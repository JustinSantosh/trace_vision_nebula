# TRACEVISION AI — Enforcement add-on: team guide

**Last updated:** 2026-11-23 · Code: `tracevision/intel.py`, `tracevision/violations.py`, `tracevision/api.py` · Decisions: [DECISIONS.md](DECISIONS.md) E17–E20 · Overview: [README.md](README.md#enforcement-add-on-synthetic-demo-data)

The add-on builds on plate recognition. Once a vehicle has a **confident registry match**, the app can show who it belongs to and its e-challan history, issue a (simulated) challan, and flag **wrong-side driving** for a person to review.

> **Everything here is synthetic demo data.** Owner names, registration details and challans are generated by a script. Nothing queries VAHAN or the e-Challan system, and no challan is ever sent anywhere. There is no login: anyone using the app can look up vehicles and issue challans.

---

## 1. What it does

| Feature | Where in the app | Rule |
|---|---|---|
| **Vehicle record** (owner, make / model, class, fuel, RTO, registration / insurance / PUC validity, e-challan history, pending amount) | Case → select a matched vehicle → **Vehicle record** → **Look up**. Also in **Cross-camera** for links whose pooled plate is a confident match, and as a typed lookup in **Enforcement** | Shown only for a **confident** match (decision `match`). A candidate list, an ambiguous result or a partly read plate never gets a record; the API refuses it (HTTP 409) |
| **Issue / cancel a challan** | Below every vehicle record: violation (the fine fills in), location, note → **Issue challan**. Each issued challan has **Cancel** | Stored on this machine only (`runs/enforcement/issued_challans.json`). Marked "issued here" and `SYN-SIM-…` |
| **Wrong-side driving, fixed cameras** | Case → **Direction** finding; **Enforcement** tab queue | The vehicle moves against the permitted direction inside a hand-drawn road zone (camera pan removed first) |
| **Wrong-side driving, moving cameras** | Same | A car is seen **front first while it closes in, then rear**: a head-on pass. It's wrong-side only on a road declared **one-way** |
| **Review queue** | **Enforcement** tab | Every flag is a *suspicion* until someone presses **Confirm** or **Reject**. Confirming a flag on a matched vehicle raises a simulated challan. Reviewed items leave the queue ("Reviewed (N)" group, with **Reset to pending**) |
| **Audit log** | **Enforcement** tab, bottom | Every lookup, refused lookup, challan issued or cancelled, and review |

## 2. Run it

```powershell
python -m tracevision.api                         # full app (GPU machine): http://127.0.0.1:8000
$env:TRACEVISION_UI_ONLY = "1"; python -m tracevision.api   # laptop: stored results only, no models
```
- **Records, challans, the fixed-camera check and the stored moving-camera results all work in UI-only mode.**
- **Uploading a clip** (and so the wrong-side check on a new clip) needs the GPU machine. The orientation for the moving-camera check is computed automatically after each upload.
- **After pulling code changes, restart the server.** A server started before the add-on answers lookups with **"Not Found"**. Reload the page too (`Ctrl+F5`).

Command-line tools:

```powershell
python TRACEVISION_DATA/scripts/generate_vehicle_intel.py    # regenerate owner records + challans (seeded, same output every time)
python -m tracevision.violations                             # wrong-side check over stored clips, printed per clip
python -m tracevision.violations --orient --jobs             # (GPU / CLIP) recompute orientation caches, including uploads
python -m pytest tests/test_intel_violations.py              # tests for this add-on
```

**Start fresh:** delete `runs/audit/` and `runs/enforcement/` to clear the audit log, review decisions and simulated challans. Both are git-ignored, so each machine has its own.

## 3. Demo the wrong-side clip

`TRACEVISION_DATA/raw/wrongside/ws01.mp4` (Git LFS, run `git lfs pull`) is a downloaded Delhi-flyover clip. A black SUV in lanes that run the camera's way comes towards the camera and passes it. Uploaded results aren't in git, so **each machine must analyse it once**:

1. On the GPU machine, start the full app and upload the file **under the name `ws01.mp4`**. The upload rule in `camera_rules.json` is keyed by that name and declares the road one-way.
2. When the job is done, open **Enforcement**. Expect one item: *Wrong-side driving · ws01.mp4 T5*, plate **HR11P2233** read, "no plate match".
3. Click it. The evidence shows the front seen 0:00–0:09 while the SUV grew about 10×, then the rear 0:14–0:18. **Open the case and play the clip**; the **Direction** finding has buttons to jump to each moment.
4. **Confirm** it. No challan is raised, because HR11P2233 isn't in the synthetic registry (it's a real plate from a public video, so we don't give it a fake owner).

Records and challans: open **clip03 → T1** (`DL3CCY1025`) or **clip12 → T1** (`CG04NL3024`), then **Vehicle record → Look up**. Every vehicle the system can match has 2–4 challans with at least one pending.

## 4. Add a wrong-side clip

Rules live in **`TRACEVISION_DATA/cameras/camera_rules.json`**.

**Fixed camera** (`cameras` section, keyed by `camera_id` in `evaluation/clips.csv`):
1. Pick a **reference frame** and draw the road zone on it as a polygon in normalised coordinates (x / width, y / height).
2. Set `allowed_direction` to the permitted direction of travel in the image: `[0, -1]` is away from the camera (up the frame), `[0, 1]` is towards it.
3. Run `python -m tracevision.violations`. Camera pan is estimated against the reference frame automatically and cached in `runs/<clip>/camera_motion.json`.

```json
"cam_fixed_overpass_01": {
  "reference_frame": 60,
  "zones": [{"name": "one-way carriageway", "allowed_direction": [0, -1],
             "polygon": [[0.30, 0.45], [0.70, 0.45], [1.0, 0.70], [1.0, 1.0], [0.0, 1.0], [0.0, 0.60]]}]
}
```

**Moving camera** (`moving` keyed by `camera_id`, or `uploads` keyed by the uploaded file name):

```json
"uploads": { "ws01.mp4": { "layout": "one_way", "description": "…" } }
```

| `layout` | Meaning | A head-on pass is… |
|---|---|---|
| `one_way` | every lane in view runs the camera's way | **flagged as wrong-side** |
| `two_way` | oncoming traffic is allowed | never flagged (normal oncoming traffic) |
| not set | unknown | flagged **for review**, with the caveat that it may be oncoming traffic |

**Filming tips:** keep the camera still if you can (fixed rule). Include vehicles going the normal way, so we can show they aren't flagged. Note the time the wrong-side vehicle appears, so the result can be checked. Never film anyone breaking the law on purpose; use a parking lot's one-way lane, or footage you already have.

## 5. How the checks decide

**Fixed camera** (`violations.check_track`). The point used is the bottom-centre of the box, where the vehicle touches the road. It is first mapped onto the reference frame: ORB features on the background, with every vehicle box masked out, matched straight to the reference frame (RANSAC). clip06's "fixed" phone camera pans about 200 px; without this, parked cars sweeping across the image looked like oncoming traffic. A vehicle is flagged only if all of these hold:
- it is in the zone for **≥ 8** detections and moves **≥ 6 %** of the frame height there
- its movement is **> 120°** off the permitted direction
- **≥ 70 %** of short steps go against the flow

**Moving camera** (`violations.head_on`). CLIP zero-shot scores each sampled crop "headlights and grille" against "red tail lights and boot". A car is flagged when:
- its front is seen clearly (score **≥ 0.8**) on **≥ 3** crops while its box grows **≥ 2×** (it closes in facing the camera; an overtaking car's flank doesn't grow like that)
- its rear is then seen (score **≤ 0.3**) on **≥ 3** later crops

Cars only: a rider hides a two-wheeler's front and rear. The thresholds are constants at the top of `tracevision/violations.py`.

**Results** (the honest version for judges):

| Check | Result |
|---|---|
| Fixed cameras (clip02, clip06) | 54 vehicles checked, **0 flagged**. No wrong-side event was filmed; the rule does flag clip02's real tracks when they are replayed backwards (unit test) |
| Moving cameras | `ws01.mp4`: the wrong-way SUV is flagged, nothing else. **0 other flags** over 214 cars in 31 clips (our 17 moving clips plus earlier uploads) |
| Front/rear classifier | 18 of 20 eye-checked crops right |

It is **one real positive example**, so this shows the method works; it isn't a detection rate.

## 7. API

| Method and path | Does |
|---|---|
| `GET /api/intel/meta` | Lookup reasons, violation types and fines |
| `GET /api/intel/{reg}?reason=&context=runs/clip03:T1` | Full record. With `context`, refused (409) unless that vehicle is a confident match to `reg` |
| `POST /api/challans` `{registration_number, violation, fine_inr?, location, note, context?}` | Issue a simulated challan |
| `POST /api/challans/cancel` `{challan_id}` | Cancel one issued here |
| `GET /data/{runs|jobs}/{id}/violations` | Wrong-side result for one run, with per-vehicle measurements |
| `GET /api/violations` | All flags (stored clips and uploads), clips assessed, simulated challans |
| `POST /api/violations/review` `{violation_id, decision: confirmed|rejected|pending, note}` | Review a flag; a confirmed flag on a matched vehicle raises a challan |
| `GET /api/audit` | Audit log, newest first |

## 8. Troubleshooting

| Symptom | Fix |
|---|---|
| "Not Found" when pressing Look up | The server was started before the add-on was pulled. Restart it and reload the page |
| "this vehicle has no confident registry match" | Expected: records only attach to confident matches. Use the typed lookup in Enforcement for a plate you already know |
| Direction says "vehicle orientation has not been computed" | Run `python -m tracevision.violations --orient --jobs` on a machine with `open_clip_torch` |
| An uploaded moving-camera clip flags normal oncoming traffic | Declare its layout `two_way` under `uploads` (or `moving` for a stored clip's camera) |
| ws01's SUV isn't flagged | It was uploaded under a different name, so the `one_way` rule didn't apply. Re-upload it as `ws01.mp4`, or add the new name under `uploads` |

## 9. Limits (say these if asked)
- All owner and challan data is synthetic, and there is no access control.
- Wrong-side driving was never filmed by us; the moving-camera check rests on one downloaded clip.
- The moving-camera check needs the road layout declared, and covers cars only.
- `ws01.mp4` is a downloaded clip (not our footage) in a public repo, with a real plate. It was the owner's choice (E20); remove it if the uploader or the vehicle owner objects.
